## 变化内容

依据：基于 `71cf9d1` 的 V0.5 提交 diff。

- [架构](../architecture.md#关键设计取舍)新增“加法以核心价值为准”的判断标准。
- 根因：18 条中有 8 条源于同一缺口。自 `8c6671b` 起，iteration 须在用户命名版本后才建，未命名的进行中工作只能溢出到 index 的“当前接续”、architecture 或 brief，于是一个决定要改多处、候选混入架构、取代写法不一。两个项目的 Agent 各自在不同文件里搭了相同的临时结构。
- [Skill](../../SKILL.md) 新增三处：
  - 未命名的进行中工作记在 `Unreleased/iteration.md`，命名后改为版本目录；index 只放当前状态、下一步与导航。
  - 不记密码、密钥、令牌，原话里的也去掉；仓库公开时不写本机绝对路径、会话或消息 ID 和他人信息。pjkp 自身的“附原话”规则正是泄漏通道。
  - 入口指针未获答复不算拒绝，下次归档时再问一次。
- 收紧现有表述：
  - 决定与候选的原话、状态只在 iteration，brief 与 architecture 只写生效结果并链接；候选不进 brief 与 architecture；Agent 自行做的取舍注明未经用户确认。
  - 接手时用 git 对照记录中的核对提交；未提交、未推送等易过期状态只写在当前状态里；验证写明做到哪一步。
  - 运行环境（路径、端口、账号名）归 architecture；Agent 私有记忆不能代替 pjkp。
- 删减：去掉只对旧机制有意义的“也不要求 plan/execute 或关闭事务”“不要求脚本或运行时依赖”，以及评估本项目收益的一句（简介已有）。本项目的“发布不等于验收”类声明，pjkp 内只留简介一处，README 留一句。
- 模板：index、iteration、architecture、project-brief 的提示语同步；rules 模板不变，未新增模板。SKILL.md 从 2,203 字变为 2,476 字（+12%），略高于规划时估计的 +9%。
- 本项目说明：README、VERSION、index、简介与架构指向 V0.5；架构中的本机路径改为 `~` 形式，并补记服务器上的安装方式。

验证（静态检查，2026-11-05）：skill-creator 的 quick_validate 通过（`Skill is valid!`）；`git diff --check` 与新文件空白检查通过；除旧日志外全部 Markdown 的 82 条相对链接与锚点有效，外链未访问；与 V0.4 相比，V0.1–V0.4 记录、旧日志、rules、AGENTS.md、展示元数据与 rules 模板未变；新增内容中没有本机绝对路径、会话 ID 或凭证。检查脚本只放在临时目录，不进仓库。未做真实项目试用或独立新会话的行为测试。
