# project-keeper 架构

> 状态：V0.1 已发布，本文包含 V0.2 开发分支的首批实现，尚未用户验收；更新日期：2026-10-20。具体操作契约以对应参考文件为准，数据章节以模板为准，实现细节由源码和测试承载。

## 整体架构

### 组成与职责

这是一个单个多 Action Skill，不是独立服务或 Plugin。Agent 负责理解用户、决策澄清、读写项目知识、修改代码和执行测试；Python 标准库辅助脚本负责定位、生成、结构校验、导航、日志以及关闭恢复记录。

- `SKILL.md`：轻量入口、公共约束、Action 路由与读取纪律。
- `references/`：按项目操作、规划、执行与测试、关闭与撤销分组的执行说明；CLI 和验证说明按需读取。
- `assets/templates/`：项目与版本文档的必备章节，作为结构校验的依据。
- `scripts/project_keeper.py`：确定性命令行辅助能力，不运行受管理项目的代码或测试。
- `tests/`：临时项目自动化测试、读取量测量和初版验证记录。
- `agents/openai.yaml`：Skill 的 Agent 展示与发现元数据。
- `pjkp/`：本项目自身的管理资料，与可复用模板、脚本职责分开。

### 受管理项目的信息布局

所有受管理项目独立使用根目录 `pjkp/`。项目级文件为 `index.md`、`project-brief.md`、`architecture.md`、`rules.md`、`roadmap.md`、`log.md`，各自记录导航、项目认识、架构、约束、规划与历史；`config.toml` 仅预留注释，不读取任何配置字段。

每个用户指定的 `Vx.x/` 按阶段生成 `requirements.md`、`spec.md`、`test-plan.md`、`test-results.md`。需求文件承载版本意图、用户验收结论与版本结果；测试文件保存执行证据，不能代替用户验收。关闭恢复记录位于目标版本 `.operations/`。本项目已有 V0.1 基线资料和 V0.2 开发资料，基线发布未补造正常迭代关闭历史。

## 关键机制与设计取舍

### 完整保存，分层读取

入口只承载路由和共同约束，操作说明与模板按任务加载。`context` 返回路径、标题、大小和指纹，`read` 提取原文章节或日志条目；默认不展开全部旧版本、日志和快照。已完整读取且未变化的内容可复用，冲突或缺少依据时扩大读取。这样减少无关输入，而非用有损摘要替换原文。

### 会话内记录与跨会话恢复

两种场景使用同一份随项目保存的上下文。会话内，Agent 将后续仍需使用的信息、决定、进展和未决问题写入职责对应的文件，需要时回读；跨会话，新 Agent 从 index、rules 和 project-brief 建立整体认识，再按任务定位架构、版本材料和关联日志。记录发生在任务推进时，恢复不依赖原会话仍然存在。

项目级文档承载当前项目认识，版本材料承载一次迭代的意图、方案与证据，log 承载行为历史。具有“草稿”性质的假设或讨论结论必须标明来源与确认状态；写入文件、在新会话中读取或进入摘要，都不改变其确认状态。文档还需保留适用范围与相关依据，以便恢复时检查是否过时。

现有指令、文档和读写命令提供承载与导航能力，实际捕捉、分类和更新由 Agent 主动完成。当前没有自动捕获整段对话、判断窗口即将溢出或独立草稿区的实现；它也不直接扩大宿主的上下文窗口。“外部记忆”描述的是文档的使用方式，两个场景下的真实接续效果仍待验证。

### 阶段性生成与依据检查

初始化只补缺失文件，不覆盖已有内容；版本产物按阶段要求生成和校验。需求、spec、代码记录和测试材料的指纹用于发现依据变化；Agent 仍需判断语义影响与真实覆盖范围。指纹只覆盖显式记录材料，不代表完整源码树、依赖或外部环境未变化。

### 规划内容来源门槛（V0.2 开发实现）

愿景与长期规划、里程碑和 todo 仍按自然语言保存。受控入口按模块比较前后正文，变化模块必须提供用户原话和来源；独立 roadmap-update 与关闭准备阶段复用检查。写入提案绑定前指纹、目标全文与同步摘要，来源进入日志，关闭时也保存到持久操作中。

新模板使用 todo，旧短期待办标题只读兼容并提示，校验不修改已有正文。规则不把历史 Agent 草案追认为用户规划，未改变模块不补造来源。单独结构校验、来源字段存在和整体版本验收，都不能证明每项自然语言规划忠实于用户；仍需 Agent 对照原消息。外部编辑器不受本入口约束。

### 行为记录与可续接

日志以独立行为为单位，子行为通过关联标识连接。同一标识、同一正文重复提交去重；新一次执行使用新标识。执行记录绑定版本与相关依据，正文仍需提供真实结果。脚本记录不是事实生成器，也没有用户身份认证。

### 关闭与撤销

关闭前保存原内容、预期内容及文件指纹，应用后记录实际结果；跨文件中断保留可续接状态，不宣称原子完成。撤销仅处理目标关闭：无后续编辑时可恢复，有变化则保留当前内容并报告冲突，结合前后材料合并；未解决前保持部分恢复状态。不依赖 Git 或对话记忆，不撤销代码、测试或部署，也不删除历史。

### 安全与运行边界

路径、符号链接越界、同名冲突及失效写入依据由辅助脚本检查。写锁只协调本脚本；单文件原子替换不等于跨文件事务，不能保证外部编辑器并发、恶意竞态或断电下的完整事务一致性。后台监听、自动部署和多人实时协同不在初版范围。

运行代码仅依赖 Python 标准库，接口声明 Python 3.9+；早期验证环境为 Python 3.14.6，V0.2 本轮在 Python 3.9.6 运行 53 项测试通过，其他版本未有实机验证记录。实际执行权限取决于宿主 Agent 环境。

## 实现入口

- [Skill 入口](../SKILL.md)：公共约束与 Action 选择。
- [项目操作](../references/project.md)：初始化、更新和接续；[规划](../references/planning.md)：版本创建和 plan。
- [执行与测试](../references/execution.md)：代码与测试的执行依据、记录及失效检查。
- [关闭与撤销](../references/closing.md)、[关闭接口](../references/close-cli.md)：验收门槛、持久化操作和恢复。
- [通用接口](../references/cli.md)、[辅助实现](../scripts/project_keeper.py)：定位、生成、校验、指纹、日志与命令行为。
- [规划来源与写入](../references/roadmap.md)：逐模块用户来源门槛、独立维护和关闭同步。
- [模板目录](../assets/templates)：各类文档的精确章节；不在本文件重复完整格式。
- [自动化测试](../tests/test_project_keeper.py)：机械约束与异常恢复；[读取量测量](../tests/measure_context.py)：场景输入量比较。
- [验证记录](../tests/verification-report.md)：已验证能力与限制；Agent 真实项目行为质量尚需试用。
