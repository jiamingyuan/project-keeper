# project-keeper 架构

核对：2026-10-23 工作树（基于 d6bb7b5，当前改动未提交）。

## 整体架构

本版是指令与 Markdown 模板，不含运行时程序。宿主 Agent 使用自身文件能力读写项目资料；自动选择 Skill、加载项目入口及上下文压缩均属宿主行为。

- [SKILL.md](../SKILL.md)：共享读写、来源与授权纪律。
- [展示元数据](../agents/openai.yaml)：让已有 pjkp 项目的普通任务和接续请求更易发现 Skill；保留默认自动发现。
- [模板](../assets/templates)：只为创建对应文档时提供内容示例，不是 Schema。
- pjkp/：每个项目独立的知识与版本记录。本目录是 project-keeper 自身的项目资料。
- [项目入口指针](../AGENTS.md)：本项目任务先读 index 和 rules，不引入后台或宿主钩子。

## 关键设计取舍

当前内容与历史分开：index 只指路，rules 只保留有效约束；版本当前部分给出进展和下一步，被取代的决定及关键原话留在同一 iteration.md 中，不用阶段枚举冒充项目事实。

来源与事实分开：用户定义方向，Agent 可依据真实成果更新事实。原话和 diff 支持审阅，不构成身份认证；版本记录中的任务指令只限定该任务范围，不向后来的新任务授予权限。

读写以有价值的事件为触发，不为维护体系本身生成日志。普通 Markdown 可用文件搜索与章节回读，不要求先运行 CLI、计算指纹或填写提案。

安全交给宿主编辑能力与可恢复原文：先读后改、保留他人编辑，大改前保全未提交内容；Git 可用但提交不是读写前提。不再实现跨文件关闭/undo 事务或并发保证。
