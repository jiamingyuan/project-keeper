# project-keeper 项目简介

## 项目介绍

### 项目定位

Project Keeper 是软件项目的轻量项目记忆，补充源码和 Git 难以表达的背景、约束与决定。用户定位原话：“agent能够快速了解项目整体context和当前状态从而提效项目开发”。

它帮助同会话找回较早信息、跨会话接续，不规定用户如何规划、编码或测试。

### 项目概要

Agent 在项目自身的 pjkp/ 中维护 Markdown。index 指向当前内容，rules 保留稳定约束，版本用单份 iteration.md 记录目标、决定、todo 与结果；按任务回读，不默认加载全部历史。指令和模板提供约定，不运行独立服务或状态机。

### 项目价值

- 减少重复解释背景和纠正过期信息。
- 保留决定的来源及取代关系。
- 让中断后的工作有明确接续点。

以上为预期价值，真实收益尚待项目对照验证。

### 长期愿景

用户方向（本对话）：聚焦软件项目，不限定个人或多人协作；长期兼容轻量与较重项目。本版不实现多人并发或规模适配。

用户原话（本对话，旧 roadmap 已记录）：

- 轻量化：“整个skill足够轻量，不会在开发之外额外消耗过多token，保障token使用的高效性。”
- 无感化：“不需要用户进行过多额外操作，也不需要用户显式调用pjkp，skill也会在用户的对话过程中根据需要自动被唤醒，而且在回复用户的对话中主动提到调用了pjkp。”

## 项目功能

- 初始化：用户要求后补齐最小资料，经同意追加宿主入口指针，不自动开始开发。
- 接续：先读 index、rules 与当前版本，按任务读取简介、架构和历史。
- 记录：在有价值的变化发生时更新当前内容，保留来源与被取代决定；不记录读取、工具步骤或无变化检查。
- 版本：用户命名版本并要求提交或归档时建立或续写单份迭代记录，兼容 PR 和直接提交，也支持提前命名并要求记录。以实际变更为骨架、会话背景为补充，同版本持续更新，不将提交视为验收或发布。

宿主是否加载指针或匹配 Skill 不由本 Skill 保证，也不检测压缩。当前实施与验证进度以 [V0.2](V0.2/iteration.md#当前状态) 为准。
