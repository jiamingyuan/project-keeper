# project-keeper 项目简介

> 状态：V0.1 基线已发布，V0.2 首批实现正在开发分支等待用户审阅，尚未验收关闭；真实会话使用效果仍待验证。更新日期：2026-10-20。

## 项目介绍

### 项目定位

Project Keeper 是 Agent coding 过程中的外部上下文管理 Skill：将项目上下文从对话中持续沉淀为可追溯、可按需读取的项目文件，帮助 Agent 在当前会话中推进工作，并在新会话中快速接续。

它主要解决两个问题：同一会话中，较早的信息可能逐渐离开当前上下文窗口，需要在窗口之外记录并按需找回；跨会话时，新会话需要通过项目文档快速理解项目全貌和当前状态，减少重新解释背景的成本。

项目背景、决策、约束和进展也不能仅靠源码完整表达。上下文随软件项目保存，面向个人与多人协作，长期兼容轻量化与较重项目；规模适配和多人并发能力仍属于长期方向。

### 项目概要

采用单个多 Action Skill，以随项目维护的 Markdown 文件系统作为外部记忆。Agent 将需要保留的背景、结论、工作进展和未决问题写入对应文档，后续按任务读取；项目认识随已确认决定和真实成果持续更新。

同一会话中的使用类似外部工作记录，帮助保存阶段性状态；跨会话时，这些记录与项目简介、架构和规则共同组成交接依据。工作记录中的假设、候选方案与已确认决定需要明确区分，避免后续读取时把讨论过程当作正式结论。

复用指令、模板与辅助脚本在 Skill 中维护；各项目的数据独立放在自身 `pjkp/`。信息完整保存、按需加载，导航和摘要不取代原始依据。版本生命周期提供需求、规划、执行、测试和收尾中的上下文维护路径。

### 项目价值

- 减少同一会话对窗口内记忆的依赖，使较早信息和阶段性工作可找回。
- 缩短新会话理解项目全貌与恢复开发的准备时间。
- 减少用户重复解释背景和约束的成本。
- 减少遗漏规则、混淆状态或沿用失效依据造成的返工。
- 使决策、实际进展和验证结果可追溯、可纠正。

以上为预期价值；实际效率收益仍需真实任务验证。

## 项目功能

初版已提供以下功能的操作指令、对应模板及确定性辅助能力。语义判断、开发和实际测试由使用 Skill 的 Agent 执行，辅助脚本不替代这些工作。

### 会话内的上下文记录与使用

在推进任务时保存需要持续使用的信息、已确认结论、当前进展和未决问题。较早信息离开当前窗口后，可按关联文档和记录重新读取，帮助继续工作。假设和候选方案保留待确认状态，不能直接写成正式需求或决定。

现有项目文档、版本材料和行为日志提供记录载体，章节、版本和日志标识提供读取入口；记录与回读依赖 Agent 在任务中主动执行。

### 跨会话的项目理解与接续

新会话先建立项目目标、功能、架构和约束的整体认识，再根据任务读取当前状态、相关版本、证据与未决问题，判断从哪里继续。支持按章节、版本和日志标识读取原文，避免为了理解全貌而默认加载全部历史。

### 项目启动：project-initiate

根据用户想法和已有材料建立上下文。信息不足时按决策影响选择澄清或多轮讨论，也允许先保留不完整草稿；不编造未知事实。

### 项目同步：project-update

依据对话中的已确认决定和实际成果，更新项目简介、架构与规划，检查受影响版本材料，区分目标、方案和实际能力。

### 版本创建：version-create

按用户指定的 `Vx.x` 建立版本目录与需求定义；同名版本先核对再续接，后续持续完善需求。

### 迭代规划：plan

结合需求与真实代码生成 spec 和测试方案，把发现的需求问题回写需求定义，并在依据变化后检查适用性。

### 执行与测试：code-execute、test-execute

依有效方案进行代码变更和测试，保留真实执行批次、结果、失败和未执行项；相关材料变化后不自动沿用旧证据。

### 版本关闭与撤销：version-close、undo

在代码执行、测试执行完成且用户明确验收通过后关闭版本，记录结果并同步项目认识、规划和入口。持久化恢复材料支持撤销目标关闭；后续编辑冲突需要核对合并，不回滚代码或测试，不删除历史。

### 历史与规划维护

每个独立行为记录一条日志，条目内可有多个要点；子 Action 单独记录并关联。规划维护长期方向、里程碑和 todo，内容来自用户提出的信息。

V0.2 开发实现提供逐模块用户来源门槛：独立更新通过受控入口写入，关闭同步也检查来源，缺少原话或来源时拒绝。旧标题可读取，不自动重写历史规划。程序无法认证来源真实性或判断转述是否忠实，Agent 仍需核对消息；计划不代表交付或执行授权。
