# project-keeper 规划

## 愿景与长期规划

面向软件项目，让个人开发者与多人协作团队都能通过随项目保存的上下文文件系统，高效地与 Agent 共同推进开发。未来同时兼容轻量化与较重项目，使信息组织、描述深度与维护成本适应项目复杂度。

- 帮助 Agent 快速接手项目和跨对话接续，减少重复解释与理解。
- 串联需求、规划、执行、测试与版本收尾，使变更后的重审和中断续接有据可依。
- 让项目描述、规划和历史跟随实际进展更新，保持事实与目标的区别。
- 在真实任务中验证不同规模与协作方式，观察信息准确性、上下文读取成本和维护负担。

以上是已确认方向，不代表规模适配、多人并发或效率收益已经实现。后续配置字段、协作机制及 Plugin 包装均需另行讨论，不作为本次实施范围。

## 里程碑

沿用早期规划的阶段划分，根据现有产物更新状态；里程碑不是发布版本，不承诺日期。当前没有关联版本。

| 标识 | 阶段成果与判据 | 当前证据与状态 |
| --- | --- | --- |
| M1 | 形成可实施的文档职责、Action 边界与恢复设计 | 初版已落入指令、模板、脚本和需求追踪；后续调整仍需依据试用反馈 |
| M2 | 上下文初始化、读取、更新与记录流程可运行，项目数据独立 | 已有对应工具与自动化覆盖；2026-09-27 开始在本项目自身使用，语义准确性与跨对话接续待观察 |
| M3 | 版本流程与关闭/undo 的确定性机制可运行 | 初版自动化覆盖相关状态和异常路径，2026-09-27 重新运行 42 项测试通过；真实项目完整 Agent 流程尚未验证 |
| M4 | 真实使用检验并持续改进 | 自身项目试用开始；尚无足够真实任务证据评定效率、维护成本或复杂协作效果 |

初版验证细节与限制见 [验证记录](../tests/verification-report.md)。以上不构成用户版本验收。
