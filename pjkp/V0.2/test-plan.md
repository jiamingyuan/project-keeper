# project-keeper V0.2 测试方案

> 状态：ready；完成测试后仍需用户验收。

## 测试依据与范围

依据 [需求](requirements.md) 与 [spec](spec.md)，覆盖 todo 命名、旧标题兼容、规划来源门槛、受控写入、关闭同步和既有行为回归；不覆盖用户身份认证和自然语言语义准确性。

## 环境与前置条件

Python 标准库测试；在临时项目中执行，不访问真实项目或远端。Skill 格式检查使用临时验证 venv 中的 PyYAML，运行脚本无第三方依赖。

## 测试场景与步骤

- 新建项目应出现 todo；旧短期待办标题可校验，正文不被改写。
- 对规划每个受影响模块分别尝试无来源、空来源、错误类型、遗漏来源和合法来源；非法请求不得改正文或新增成功日志。
- 提供过期指纹应拒绝写入；合法更新保存目标全文和来源日志；重复提交与写后日志中断续接不能覆盖后续编辑。
- close prepare 中规划变化无来源应失败，有对应来源应成功并在关闭日志保留来源；既有 undo 行为持续回归。
- 查询并渲染每个 Action 的日志定义；分别测试缺少章节、空值、非字符串、错序、未知行为和标题注入，写入失败不得新增成功日志或执行完成状态。
- 检查新日志统一头部、可读状态行、必备章节和机器证据；覆盖自动生成的 roadmap、关闭子更新、部分关闭和 undo。
- 读取并校验混合新旧格式的日志，重放旧关闭与旧执行记录，不改写历史；同 id 不同内容仍拒绝。
- `python3 -B -m unittest discover -s tests -v`：运行全部测试。
- skill-creator 的 `quick_validate.py`：检查 Skill 格式；辅助脚本 `validate --version V0.2 --stage test`：检查本项目结构与链接。

## 通过标准

新增场景与既有回归全部通过；格式和项目结构无错误，告警按真实原因说明。测试执行与测试通过、用户验收分别记录，不能自行执行 version-close。

## 未覆盖与待确认事项

未做独立模型端到端评测、其他 Python 版本实机验证或复杂项目协作实验。来源门槛不证明来源真实性，仍由 Agent 对照真实用户消息检查。
