## 规划依据

[V0.2 需求](requirements.md)、[项目规则](../rules.md)、用户已有两项 [todo](../roadmap.md#todo)；实际入口为 scripts/project_keeper.py、references 中项目/关闭操作、roadmap/index 模板与自动化测试。

## 当前实现与约束

V0.1 有七个主要 Action、undo、42 项测试，采用标准库。roadmap 模板仍使用短期待办，自身文件已经使用 todo，导致校验报错。规划正文主要依赖 Agent 维护，关闭提案目前没有逐模块来源门槛。

## 变更方案

- 模板统一 todo，校验兼容旧标题并报告升级提示，不改写旧正文。
- 增加按二级模块比较前后内容的来源检查；发生变化的模块需要非空用户 statement 和 source。来源记录是调用者的据实声明，不是身份认证。
- 增加 roadmap-update 辅助命令：提案携带文件前指纹、目标全文、逐模块 sources、同步摘要；先检查再写入并记录日志。允许同一提案在写后日志中断时续接，拒绝覆盖其他编辑。
- close prepare 复用来源检查，受影响模块的来源保存进持久操作和日志。未改变 roadmap 不需要新增来源。undo 使用既有恢复记录，不重新生成规划。
- 在按需说明中定义写前门槛，SKILL.md 仅保留关键规则与链接。不修改全局注册或其他 Skill。
- 日志规范通过单一 JSON 字段定义驱动：三级章节顺序与含义按 Action 定义，支持 JSON 数据渲染与规范 Markdown 输入。轻入口链接通用说明，log-schema 只返回所需 Action。
- 新日志写入及项目 validate 检查 schema=1 的格式；旧日志不重写，旧关闭/撤销/执行记录的续接维持原格式和去重标识。
- 自动生成的 roadmap、关闭子更新、部分关闭和 undo 使用同一渲染；机器执行证据单独展示。新增非法结构、空字段、各行为渲染、重试和历史混用测试。

## 待确认与待重审事项

本版不能自动确认原话确实来自用户、判断提案是否忠实转述，也不能禁止外部编辑器写文件。这些边界不阻塞入口约束实现，真实 Agent 行为效果继续待试用。V0.1 标签保持固定，V0.2 最终关闭等待用户验收。
