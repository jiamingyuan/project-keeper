# 维护验证与需求追踪

仅维护或验收本 Skill 时读取；普通 Action 不加载此文件。

## 运行

```text
python3 -B -m unittest discover -s <skill>/tests -v
python3 -B <skill>/tests/measure_context.py
python3 <skill-creator>/scripts/quick_validate.py <skill>
```

测试在自动清理的临时目录中生成样例项目，并实际运行一个 Python 示例测试。它验证机械约束与断点恢复，不证明所有 Agent 在自然语言场景中都能正确决策。上下文测量使用 UTF-8 字节数，不称为精确 token 数或延迟提升。

## 设计要求到实现的映射

| 要求 | 实现/维护来源 | 验证方式 |
| --- | --- | --- |
| 单 Skill、七 Action、按需路由 | SKILL.md，四组 references | 链接检查；人工核对路由与独立读取清单 |
| 项目 pjkp 隔离、配置只预留 | init/root_path/safe，config 模板 | 多项目、嵌套定位歧义、未采用项目不初始化、路径与符号链接测试 |
| 可选 brainstorming、不编造 | project.md，各模板待确认项 | 草稿初始化测试；多轮澄清的语义判断留待实际试用 |
| 项目简介两个模块、源码之外的架构知识 | brief/architecture 模板、project.md | 结构测试；人工检查架构未硬编码 Skill Action |
| 每版 Vx.x、同名续接、按阶段生成 | planning.md，version-create/scaffold | 非法编号、目录存在、阶段校验、已关闭版本不能直接编辑测试 |
| 基于真实代码规划、问题回写、变更传播 | planning/execution，basis/readiness | 需求回写、方案/实现变更失效测试；方案质量依赖 Agent |
| 实际执行/测试、证据与用户报告区分 | execution.md，record，批次模板 | 实际样例测试、失败/未执行证据保留、旧执行记录失效 |
| 用户验收才关闭，不等于发布 | closing.md，prepare | 无验收、无执行记录、过期依据、提案冲突拒绝 |
| 双描述/规划/索引同步与 undo | 关闭提案及操作记录 | 中断、后续编辑、冲突合并、重复 apply/undo、重新关闭、后续版本摘要保护 |
| 每行为一条 log，子行为关联，历史保留 | 各 Action 日志约定、append_log | 去重、更正追加、原历史保留、日志写入中断恢复 |
| 轻上下文但不覆盖原知识 | 导航、指纹、原文章节提取、路由表 | 原文提取测试；四场景读取字节测量；冲突扩大读取属人工检查 |
| 不依赖 Git、不部署、不安装或注册 | 标准库 helper、交付路径 | 临时项目无 Git；源码/测试保留；无注册代码 |

## 初版适用边界

模板为初版结构契约，正文的事实和完成判定仍由 Agent 依据用户与产物维护。项目有定制结构时，先和用户讨论调整 Skill/模板，不为了通过校验删除知识。

文件指纹覆盖被显式记录的实现文件和关联文档，不覆盖完整外部环境。无用户身份验证；假执行记录和伪造验收不是脚本能够识别的全部问题。不要报告“通过脚本检查所以用户已验收”。

操作快照保留完整 before/after；自动 undo 保守处理整份文件，有新编辑时需要语义合并。当前仅本脚本写锁与乐观指纹检查，非多人实时协作或恶意竞态防护。详见 [辅助接口限制](cli.md)。

待实际试用：模糊想法的多轮澄清、复杂源码架构提炼、真实项目需求映射、跨对话恢复质量、合并冲突判断，以及在不同模型上的上下文/耗时收益。
