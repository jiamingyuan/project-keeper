# 规划内容来源与受控写入

仅在初始化填写规划、独立维护 roadmap、project-update 或关闭同步涉及规划变更时读取。它是已有规划维护能力的辅助入口，不增加主要 Action。

## 写前门槛

愿景与长期规划、里程碑、todo 的内容必须来自用户提出的信息。逐个核对受影响模块对应的用户原话和来源；允许忠实整理表达，不自行拆解里程碑、补任务、承诺日期或把推测变为目标。用户采纳 Agent 建议后才可依据采纳消息记录，未采纳的建议留在对话。

没有来源就保持原文或待用户提供。初始化模板为空是合法状态，不为填满章节编写内容。历史文件中没有出处的内容不能因升级自动视为用户已确认，需说明缺口。

正文中保留可读来源说明；写入提案还要按变化模块提供来源，用于入口检查与日志。程序只检查声明存在、变更范围和写入依据，不认证身份或判断自然语言忠实度，Agent 必须对照真实消息。

## 独立规划维护

先读取当前全文与指纹，用 apply_patch 在临时位置创建提案 JSON；不要直接覆盖项目 roadmap。`after` 是目标全文，保留原标题前内容和三个模块；不改其他模块时保留原文。旧短期待办标题可读取，更新时使用 todo。

```json
{
  "before_sha256": "<当前全文指纹>",
  "after": "<目标全文>",
  "summary": "<用户要求及实际变化>",
  "sources": {
    "todo": {"statement": "<用户提出或明确采纳该内容的原话>", "source": "<对话消息、日期或用户文档位置>"}
  }
}
```

`sources` 必须覆盖每个正文变化模块，键为愿景与长期规划、里程碑、todo；只改旧标题为 todo 而不变正文不增加规划意图。运行：

```text
--project <root> roadmap-update --id <本次行为id> --proposal <JSON路径>
```

命令检测过期指纹、结构和来源，保存目标正文并记录一条 roadmap-update 日志，包含来源、摘要和前后指纹，不再额外调用 log。写后日志中断可用同一提案和 id 重试；已完成提案重试不覆盖后续编辑。不同内容使用旧 id 会报错。

此入口不认证用户身份，也不能阻止外部编辑器绕过它。单独 validate 校验结构，不证明正文每条信息都有真实用户来源。

## 关闭与撤销

关闭时若 roadmap 模块正文有变化，在关闭提案提供同形状的 `roadmap_sources`，由 close prepare 执行同一检查并持久保存。用户验收本身不授权 Agent 随意新增未来规划；来源必须支持实际变化。无变化无需编造来源。

undo 依据持久快照撤销目标关闭，保留后续工作；冲突合并只消除目标关闭的影响，不新增目标、里程碑或 todo。新的规划修改另行走来源门槛。
